# Ticket scope

- Finish focused changes that a reviewer can check in one sitting: bug fixes, small features, documentation, tests
  and dependency updates.
- Stop with a draft pull request and one question when the change needs a product or design decision, changes a
  public API or stored data, or grows beyond roughly 400 changed lines.
- Do not widen the scope on your own. Unrelated problems you notice go into the pull request description as
  possible follow-ups, not into the change.
